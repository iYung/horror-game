# Port wip-3d Engine Improvements

## Goal

Port two meaningful improvements from `../wip-3d` into horror-game:

1. **SceneManager fade transitions** — smooth black-fade between scenes instead of instant cuts.
2. **Image-based billboard sprites** — monsters and items render as PNG images rather than colored vertical lines; the light-fog darkness mechanic is preserved.

Wall and floor rendering stay unchanged (colored lines with point-light brightness, flat rect floor).

---

## Affected files

| File | Change |
|------|--------|
| `core/lua/scene_manager.lua` | Add fade-in/fade-out state machine |
| `core/lua/raycaster.lua` | Extract `draw_sprites()` method; switch sprites from color-rects to image blits; preserve fog brightness |
| `game/scenes/run_scene.lua` | `build_sprites()` passes `image =` instead of `color =`; call `raycaster:draw_sprites()` separately |
| `assets/sprites/` | New PNG directory with placeholder sprites generated by Python script |
| `scripts/generate_sprites.py` | New script — solid-color RGBA PNGs for all billboard types |

## What changes

### 1. SceneManager fade

`scene_manager.lua` gains three fields: `_prev`, `_fade_state` (`"idle"/"out"/"in"`), `_fade_alpha`.

- On `switch()`: if a scene is already active, save it as `_prev`, call `on_enter()` on the incoming scene immediately (so it starts loading), then begin fading out the old scene.
- During fade-out: draw `_prev`, overlay a black rect at increasing alpha.
- At alpha = 1: call `on_exit()` on `_prev`, start fade-in.
- During fade-in: draw `self.current`, overlay a black rect at decreasing alpha.
- Screen dimensions hardcoded as `1280 × 720` (matches `love.window.setMode` in `main.lua`).

First `switch()` (no previous scene) skips the fade entirely.

### 2. Raycaster — split `draw_sprites()` out

`raycaster:draw(...)` currently does walls + sprites in one pass. After the change:

- `raycaster:draw(map, px, py, angle, opts)` — wall pass only; `opts.lights` still drives wall brightness; `opts.sprites` table removed from this method.
- `raycaster:draw_sprites(sprites, px, py, angle, lights)` — new method; called separately by RunScene after the wall pass.

Sprite entry format changes:

| Field | Before | After |
|-------|--------|-------|
| `color` | `{r,g,b,a}` | removed |
| `image` | — | `love2d Image` object (required) |
| `size` | scale factor | renamed to `scale` for consistency with wip-3d |
| `voffset` | — | world-unit vertical offset (positive = up, default 0) |
| `flip_x` | — | mirror horizontally (default false) |
| `setup` | — | optional fn called before drawing (shader apply) |
| `teardown` | — | optional fn called after drawing (shader clear) |

Light-fog is preserved: `draw_sprites()` accepts a `lights` argument (same format as `opts.lights`) and multiplies `setColor` brightness per sprite by the same point-light formula currently used inline.

Rendering switches from per-column `love.graphics.line()` to scissored `love.graphics.draw(img, ...)` runs (same technique as wip-3d).

### 3. RunScene — updated `build_sprites()`

`build_sprites()` loads images via `love.graphics.newImage` (lazy, cached in a module-level table) and passes them instead of color tables. Extraction zone and torches also get images.

RunScene's `draw()` becomes:

```lua
function RunScene:draw()
    local lights = build_lights(self)
    self.raycaster:draw(self.map, self.player.x, self.player.y,
        self.player.angle + self._shake_angle, { lights = lights })
    self.raycaster:draw_sprites(build_sprites(self), self.player.x, self.player.y,
        self.player.angle + self._shake_angle, lights)
    self.drawer:draw()
end
```

### 4. Placeholder sprites

A new `scripts/generate_sprites.py` (using Pillow) generates solid-color PNGs matching the colors currently used for each billboard. Output goes to `assets/sprites/`. All images are `64 × 128` (portrait, 1:2) except items (`64 × 64`) and torches (`32 × 32`).

| Sprite | File | Color |
|--------|------|-------|
| Monster | `monster.png` | `(0.9, 0.1, 0.1)` red |
| Flashlight | `flashlight.png` | `(1.0, 0.9, 0.3)` yellow |
| Flare gun | `flare_gun.png` | `(1.0, 0.2, 0.8)` pink |
| Compass | `compass.png` | `(0.3, 0.8, 1.0)` cyan |
| Tracker | `tracker.png` | `(1.0, 0.4, 0.1)` orange |
| Adrenaline | `adrenaline.png` | `(0.2, 1.0, 0.4)` green |
| Taser | `taser.png` | `(0.3, 0.8, 1.0)` light blue |
| Extraction | `extraction.png` | `(0.1, 1.0, 0.2)` bright green, 32×256 tall |
| Torch | `torch.png` | `(1.0, 0.65, 0.15)` amber, 32×32 |

## What stays the same

- Wall rendering: DDA raycasting, colored lines, point-light brightness — unchanged.
- Floor rendering: flat `love.graphics.rectangle` — unchanged.
- `opts.lights` format and the light-fog mechanic — unchanged; fog now applied via `setColor` on the image draw instead of the line draw.
- `opts.fov` — unchanged.
- All game logic: monster, player, items, extraction, inventory, traits — untouched.
- `Simulation` / headless testing — untouched (simulation never calls raycaster).
- Existing test suite — no new tests required for the fade (UI-only); `draw_sprites()` split is covered by the existing kill/extraction tests continuing to pass (they drive simulation, not the raycaster).
